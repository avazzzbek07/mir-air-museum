# Аудит безопасности · 12 ноября 2026

Проверены клиентский код, правила Firestore, границы полномочий старост, приватность анкет, публикация фотографий, новости, лайки, ссылки, защита страницы и настройки Firebase Authentication. Атаки воспроизводились в локальном эмуляторе проекта `demo-museum-security` на вымышленных данных. Реальные анкеты не выгружались и не изменялись.

## Подтверждённые проблемы и исправления

| Проблема | Риск до исправления | Исправление |
| --- | --- | --- |
| Одобренные анкеты доступны без входа | Чтение анкет и контактов прямым запросом к Firestore, в том числе массовым | Чтение полного профиля разрешено владельцу, старосте его группы и администратору. Запросы списка анкет доступны только соответствующему модератору |
| `projectPhotos` можно менять отдельно от проекта | Замена или удаление фотографий опубликованного проекта в обход модерации | Изменение фото требует атомарного перевода проекта в `pending` с актуальным серверным временем; удаление проекта с фото одним пакетом сохраняется |
| Любой староста управляет всеми новостями | Изменение и удаление новостей других групп и общих новостей | Права ограничены группой старосты; глобальными новостями управляет администратор |
| Автор новости и время публикации не защищены | Подмена автора и служебных полей | Автор при создании совпадает с подтверждённой почтой; автор и время создания неизменны; время изменения проверяется сервером |
| Анонимный аккаунт может создать анкету и лайки | Спам в базе, лишние расходы на запросы | Анонимный вход отключён в Authentication; правила запрещают такие записи. Лайки требуют одобренного студента, новые проекты — одобренного студента или модератора |
| Типы элементов навыков, тегов и групп не проверялись | Невалидные данные могут сломать загрузку страниц после одобрения | Проверяются тип, длина и количество элементов, допустимые группы и отсутствие повторов |

Дополнительно: HTML экранируется; ссылки проходят проверку протокола; CSP запрещает inline-скрипты, `eval`, плагины и подмену базового URL. Referrer отключён, одноразовые коды почтовых ссылок удаляются из адресной строки после чтения. После выхода очищаются анкеты в памяти и DOM; запоздалые ответы старой сессии не возвращают их обратно.

Серверная политика Firebase Authentication: новые и сбрасываемые пароли — от 12 символов, `ENFORCE`; принудительная смена при входе существующих пользователей отключена. Защита от email enumeration была включена и сохранена. Разрешённые домены не расширялись.

## Результаты проверок

- 13 опасных сценариев воспроизведены на прежних правилах; исправленные правила их блокируют. Это сценарии тестов, а не 13 независимых критических уязвимостей.
- 46 проверок правил и вспомогательных защит проходят, включая законные действия владельца, старост и администратора.
- Браузер: вредоносные строки отображаются текстом; опасные ссылки не создаются; inline-скрипт и внедрённый `base` блокируются CSP; проверены выход и запоздалые ответы авторизации.
- Мобильный прогон 3D-музея после защитных изменений проходит без исключений JavaScript.
- `npm audit` тестовых зависимостей: 0 известных уязвимостей после обновления транзитивного `@grpc/grpc-js` до 1.14.7. Эти Node-зависимости не загружаются посетителям сайта.
- Опубликованные правила проверены одним анонимным запросом с проекцией отсутствующего поля: запрос одобренных анкет возвращает HTTP 403. Содержимое анкет не запрашивалось для вывода и не сохранялось.

## Повторение проверок

Нужны Java 21+, Firebase CLI и `npm ci`.

```sh
firebase emulators:exec --only firestore --project demo-museum-security --config firebase.security.json 'npm run test:security'
node tools/verify-security-browser.mjs
```

Браузерный тест использует Chromium (`CHROME_PATH`) и локальную копию Three.js 0.160.0 (`THREE_PATH`, по умолчанию `/tmp/museum-three.module.js`), как описано в README. Firebase в браузерном тесте заменён изолированной заглушкой, проверка прав выполняется настоящим эмулятором Firestore. `BASELINE_RULES=/путь/к/прежним.rules` запускает 13 сценариев, ожидая прежние разрешения. Не используйте боевой проект для тестов.

## Границы защиты и оставшиеся меры

Публичные проекты, имена авторов, составы групп из `data.js`, переводы, фото и история публичного GitHub-репозитория остаются публичными. Их можно копировать без взлома. Закрытие анкет не отзывает данные, которые кто-то сохранил раньше. Нельзя хранить секреты в статических JS-файлах; Firebase web API key сам по себе не является паролем к базе.

Староста должен проверить, что регистрирующийся человек действительно учится в его группе: подтверждение email доказывает владение почтой, но не личность студента. Подтверждённый модератор по определению имеет доступ к анкетам своей группы.

Следующий уровень защиты — App Check и серверные ограничения частоты запросов/регистрации, мониторинг квот и оповещения, MFA для входа на сайт, двухфакторная защита аккаунтов GitHub и Google/Firebase, проверка IAM и резервного копирования. Эти меры не объявлены включёнными данным аудитом. Включение MFA требует регистрации второго фактора самими пользователями. Ограничения частоты нельзя надёжно реализовать одним клиентским JavaScript.

GitHub Pages не предоставляет проекту настройку произвольных HTTP-заголовков. CSP задана через HTML; директиву `frame-ancestors` и другие защитные заголовки следует задавать при переходе на хостинг с управлением заголовками. Полный аудит всей облачной инфраструктуры, почтовых аккаунтов и будущих уязвимостей зависимостей не выполнялся. Гарантии «сайт невозможно взломать» нет.

Основные первичные справочники: [Firestore: доступ на уровне документа](https://firebase.google.com/docs/firestore/security/rules-fields), [проверка атомарных записей](https://firebase.google.com/docs/firestore/manage-data/transactions), [политика паролей](https://docs.cloud.google.com/identity-platform/docs/password-policy), [защита email](https://docs.cloud.google.com/identity-platform/docs/admin/email-enumeration-protection).
